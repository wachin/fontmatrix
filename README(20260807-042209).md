# Fontmatrix Qt5 Fork

This repository is a Qt5-oriented fork of **Fontmatrix**, with the goal of keeping the abandoned project buildable on modern Linux distributions and extending it so it can work not only with fonts installed in the operating system, but also with font collections stored in arbitrary folders.

The project currently builds with **CMake + Qt5** and includes a folder-based collection mode.

> **Important:** the current source tree uses **Qt WebEngine**, not the old Qt WebKit API. The top-level `CMakeLists.txt` explicitly requires `Qt5WebEngineWidgets`.

## Current status

- Builds with CMake and Qt5.
- Preserves the traditional system-font browsing workflow.
- Can open a folder as a font collection.
- Can return to the full catalog with `File > Show All Fonts`.
- Has an explicit `File > Close Collection` action with **Ctrl+W**.
- Remembers the last opened collection.
- Can reload the current collection.
- Shows the full active collection path in the status bar.
- Stores recent collections in `File > Recent Collections`.
- Provides `File > Quick Collections` with one-click access to common font folders.
- Prevents fonts outside the active folder from leaking into collection mode.
- Exposes both `AllFontNames()` for the global catalog and `VisibleFontNames()` for the collection-filtered subset.

Functional details and pending work are tracked in [ROADMAP.md](./ROADMAP.md).

## Build dependencies

### Debian 13 / AV Linux MXe 25 and derivatives

AV Linux MXe 25 is based on Debian 13, so this is the recommended dependency set for that environment:

```bash
sudo apt update
sudo apt install -y \
  build-essential \
  cmake \
  pkg-config \
  qtbase5-dev \
  qttools5-dev \
  qttools5-dev-tools \
  libqt5svg5-dev \
  qtwebengine5-dev \
  libqt5sql5-sqlite \
  libfreetype-dev \
  libfontconfig1-dev
```

### Debian 12 / MX Linux 23 and derivatives

```bash
sudo apt update
sudo apt install -y \
  build-essential \
  cmake \
  pkg-config \
  qtbase5-dev \
  qttools5-dev \
  qttools5-dev-tools \
  libqt5svg5-dev \
  qtwebengine5-dev \
  libqt5sql5-sqlite \
  libfreetype6-dev \
  libfontconfig1-dev
```

### Why `qtwebengine5-dev` is required

The current top-level `CMakeLists.txt` contains:

```cmake
find_package(Qt5WebEngineWidgets REQUIRED)
```

and `src/CMakeLists.txt` links against:

```cmake
Qt5::WebEngineWidgets
```

Therefore, old instructions that mention:

```text
libqt5webkit5-dev
```

are no longer correct for the current source tree.

You normally do **not** need to install `libqt5webenginewidgets5` explicitly because it is pulled in as a runtime dependency of the development package.

### Other notes

- `libqt5sql5-sqlite` is important because Fontmatrix uses SQLite internally.
- FreeType is required by CMake through `find_package(Freetype REQUIRED)`.
- Fontconfig is detected on Unix/Linux and is strongly recommended.
- HarfBuzz sources are already included in this repository under `harfbuzz/`.
- The project also contains its own legacy support code for optional components.

## Optional build features

The top-level `CMakeLists.txt` contains optional support for additional components.

They are **not required for the normal build** documented above.

### ICU

Enable with:

```bash
-DWANT_ICU=true
```

### M17N

Enable with:

```bash
-DWANT_M17N=true
```

### PoDoFo

Enable with:

```bash
-DWANT_PODOFO=true
```

### PythonQt

Enable with:

```bash
-DWANT_PYTHONQT=true
```

This option also causes CMake to search for Python development libraries.

These optional configurations have not necessarily been validated recently on modern Debian releases, so enable them only when working specifically on those features.

## Building Fontmatrix

### Recommended clean build

When changing dependencies, switching distributions, or updating the source code, remove the previous build directory first. CMake caches library paths and an old cache can cause confusing errors.

From the repository root:

```bash
rm -rf build
cmake -S . -B build
cmake --build build -j$(nproc)
```

The resulting executable should be created at:

```text
build/src/fontmatrix
```

### Run without installing

```bash
./build/src/fontmatrix
```

### Install locally

```bash
sudo cmake --install build
```

On Linux, the project currently defaults to the following installation prefix:

```text
/usr/local
```

This normally installs the executable under:

```text
/usr/local/bin/
```

## Debug build

For development work, a Debug build can be useful:

```bash
rm -rf build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j$(nproc)
```

The source tree contains a number of warnings inherited from the historical Fontmatrix codebase and old Qt APIs. Warnings should be reviewed progressively, but they do not necessarily indicate a failed build.

## Troubleshooting

### CMake cannot find `Qt5WebEngineWidgets`

Example:

```text
Could not find a package configuration file provided by
"Qt5WebEngineWidgets"
```

Install the Qt WebEngine development package:

```bash
sudo apt install qtwebengine5-dev
```

Then start again with a clean build directory:

```bash
rm -rf build
cmake -S . -B build
```

### CMake still refers to Qt WebKit

The current source tree should use Qt WebEngine. If an old build directory was configured against an earlier version of the project, delete it:

```bash
rm -rf build
```

Then configure again:

```bash
cmake -S . -B build
```

### FreeType is not found

On Debian 13 / AV Linux MXe 25:

```bash
sudo apt install libfreetype-dev
```

On Debian 12:

```bash
sudo apt install libfreetype6-dev
```

### Fontconfig is not detected

Install:

```bash
sudo apt install libfontconfig1-dev pkg-config
```

Then rebuild from a clean directory.

### SQLite support is missing at runtime

Install the Qt SQLite driver:

```bash
sudo apt install libqt5sql5-sqlite
```

### Get a useful compiler error log

If compilation fails, a single-job verbose build can make the real error easier to identify:

```bash
cmake --build build -j1 --verbose
```

Or save the complete output to a file:

```bash
cmake --build build -j1 2>&1 | tee build-error.log
```

When reporting a build problem, include the first actual `error:` or `fatal error:` message, not only the final `make`/`gmake` failure lines.

## Recommended development workflow

1. Install the dependencies for the Linux distribution being used.
2. Delete an old `build/` directory when changing dependencies or CMake configuration.
3. Configure with:

   ```bash
   cmake -S . -B build
   ```

4. Compile with:

   ```bash
   cmake --build build -j$(nproc)
   ```

5. Run directly from the build tree:

   ```bash
   ./build/src/fontmatrix
   ```

6. Test both the traditional system-font workflow and the collection workflow.
7. Review [ROADMAP.md](./ROADMAP.md) before implementing additional features.

## Manual collection-mode tests

Whenever collection-related code is modified, at minimum test the following:

1. Open Fontmatrix showing system fonts.
2. Go to `File > Open Font Collection...`.
3. Select a folder containing `.ttf`, `.otf`, or `.pfb` files.
4. Verify that only fonts belonging to that folder are shown.
5. Verify that the window title and status-bar catalog label identify the active collection.
6. Verify that `File > Close Collection` or **Ctrl+W** returns to the global catalog.
7. Verify that `File > Reload Current Collection` works.
8. Verify that `File > Recent Collections` can reopen the folder.
9. Verify that `File > Show All Fonts` returns to the global catalog.
10. Verify that `File > Quick Collections` shows available locations such as `~/.fonts` and `~/.local/share/fonts` when they exist.
11. Close and reopen Fontmatrix and verify that the last collection is restored as expected.

## Changes already introduced in this fork

This fork includes support for:

- opening folders as font collections,
- switching between collection mode and the global catalog,
- explicitly closing a collection with `File > Close Collection` (**Ctrl+W**),
- remembering the last collection,
- reloading collections,
- showing the active collection path in the status bar,
- recent collections through `File > Recent Collections`,
- quick access to common font directories through `File > Quick Collections`,
- visual collection-mode indicators,
- restricting the visible subset of fonts to the active collection,
- and exposing global and filtered APIs through `AllFontNames()` and `VisibleFontNames()`.

## Important caveats

Fontmatrix is an old codebase that has gone through several Qt generations. This fork is a modernization effort, not a complete rewrite.

Keep in mind that:

- The project still produces warnings originating from legacy C++ and Qt APIs.
- Successful compilation does not guarantee that every historical feature has been fully tested on current distributions.
- Old documentation in files such as `README` and `INSTALL` may refer to dependencies or build procedures that no longer match this Qt5 fork.
- Qt WebKit references in historical documentation should not be treated as authoritative for the current tree.
- Features involving filters, family views, exports, font reloads, or database operations should be tested carefully to ensure they respect collection filtering.

## Suggested next improvements

Possible priorities include:

- continue removing obsolete Qt APIs and compiler warnings,
- test the project against current Debian releases,
- improve CMake dependency detection and minimum-version declarations,
- modernize the very old `cmake_minimum_required()` value,
- add CI builds for supported Linux distributions,
- allow multiple collections to be opened and switched between,
- add recursive/non-recursive collection options,
- allow filtering collection imports by font format,
- review secondary operations that may still rely on the global catalog,
- add automated tests,
- and eventually evaluate a future Qt6 port once the Qt5 codebase is stable.

## Project background

Fontmatrix is a font-management application originally developed many years ago and later left without active upstream maintenance. This repository aims to preserve the useful parts of the application while making it possible to compile, study, fix, and extend the software on modern Linux systems.

Contributions focused on compatibility, bug fixes, documentation, testing, and gradual modernization are welcome.
